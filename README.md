# Разряд

Платформа обратного подбора ИТ-специалистов. Работодатель находит категорию «специализация + подтверждённый тестом грейд» и сам отправляет приглашение с вилкой. Контакт кандидата открывается после принятия или собственного отклика. История ФСП усиливает ранг внутри категории. Если истории нет, человек остаётся в подборке.

Сопроводительная документация для сдачи:

- этот файл — как устроен продукт и как поднять его локально;
- [docs/soprovoditelnaya-dokumentaciya.md](docs/soprovoditelnaya-dokumentaciya.md) и [docs/soprovoditelnaya-dokumentaciya.pdf](docs/soprovoditelnaya-dokumentaciya.pdf) — тот же комплект в форме, которую просит ТЗ (архитектура, тест, подбор, валидация, реестр ФСП, API, версии, запуск);
- продуктовые решения до кода: [docs/specifikaciya.md](docs/specifikaciya.md).

Лицензия: MIT.

Прототип — каталоги `frontend` и `backend`. Каталог `strings` в запуск не входит.

## Что закрыто по ТЗ

Сделано: два кабинета, профиль формой, согласия, тест и категория, кулдаун 90 дней, приглашение с обязательной вилкой, скрытые контакты, пустая история ФСП, подборка с объяснением, фильтр достижений ФСП без потери вакансии, поиск по банку, публикация вакансии и отклик, OpenAPI, Docker.

Не сделано и в документации названо прямо: загрузка PDF-резюме и генерация PDF-профиля; регулярные короткие задания; рабочая модерация компаний и коннектор ATS (это концепция); презентация и публичный URL стенда.

## Локальный запуск для проверки

Для полного теста с задачами на код удобнее Docker: в контейнере API есть Python 3.12, которым считаются практические задачи. Локальный Python 3.11 API поднимет, но код в экзамене не засчитает, пока рядом нет 3.12.

### Docker

Нужен [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/) с бэкендом WSL 2. Порты `5432`, `8000` и `8080` свободны.

```powershell
docker compose version
docker compose up --build -d
docker compose ps
```

У `db`, `api` и `web` в STATUS должно быть `Up`. Первый запуск скачивает Postgres 16 и собирает образы. API создаёт схему и учебные учётки (`SEED=1`, почта подтверждается через `AUTO_VERIFY=1`).

| Сервис | Что это | Порт |
| --- | --- | --- |
| `db` | Postgres 16, база `razryad`, пользователь и пароль `razryad` | 5432 |
| `api` | FastAPI. Каталог `data/` смонтирован в `/app/data` только для чтения | 8000 |
| `web` | nginx со собранным интерфейсом, `/api/` проксируется на API | 8080 |

- Интерфейс: http://127.0.0.1:8080
- OpenAPI: http://127.0.0.1:8000/docs
- Проверка: http://127.0.0.1:8000/api/v1/health — `{"status":"ok"}`

Остановить, данные оставить: `docker compose stop`, снова поднять `docker compose start`. Убрать контейнеры: `docker compose down`. Удалить и базу: `docker compose down -v`. Логи: `docker compose logs -f api`. После правок кода: `docker compose up --build -d`.

На Windows, если Docker пишет, что не включён Virtual Machine Platform, в PowerShell от администратора:

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Windows-Subsystem-Linux -All -NoRestart
Enable-WindowsOptionalFeature -Online -FeatureName VirtualMachinePlatform -All -NoRestart
```

После этого нужна перезагрузка. В BIOS/UEFI должна быть включена виртуализация.

### Без Docker

Нужны Python 3.11+ и Node.js 20+.

```powershell
cd backend
copy .env.example .env
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python -m uvicorn app.main:app --reload --port 8000
```

Второе окно:

```powershell
cd frontend
npm install
npm run dev
```

Интерфейс: http://127.0.0.1:5173. Vite проксирует `/api` на порт 8000. База — файл `backend/razryad.db`. Повторный запуск учебные учётки не дублирует.

Чтобы практические задачи засчитались, нужен Python 3.12: команда `python3.12` в `PATH` или путь в переменной `PYTHON312`.

Автотесты:

```powershell
cd backend
.\.venv\Scripts\python -m pytest tests -q
```

## Как пройти сценарий

1. Войти Мариной и открыть вакансию Backend · Middle («Middle Backend на Go»).
2. Игорь в списке. На карточке написано, что истории ФСП нет. Почты и telegram нет.
3. Включить «Только с достижениями ФСП». Игорь скрывается, вакансия остаётся. Выключить — возвращается.
4. Страница «Банк»: специализация, грейд, стек и та же галочка ФСП. Это поиск по всей базе, не замена открытой вакансии.
5. Пригласить кандидата с достижением ФСП. Вилка берётся из вакансии. Контакт всё ещё закрыт.
6. Войти кандидатом, открыть приглашение, увидеть компанию, текст и вилку, принять.
7. У Марины в «Откликах» статус «принято» и появились почта и telegram.
8. Дополнительный контур: кандидат с запечатанным грейдом открывает «Вакансии» и откликается. Вакансии выше его грейда не показываются. Анна без категории список вакансий не видит.
9. Живой тест Анны: «Тест», Backend, Middle, 60 минут. 60 вопросов и 3 задачи на Python 3.12. Ключ в браузер не приходит. Ниже 65 категория не назначается. От 65 запечатывается Backend · Middle.

Короткий ход для демо без прохождения 60 вопросов — шаги 1–7 на уже запечатанных людях сида.

## Рейтинг в подборке

До счёта человек проходит ворота: профиль опубликован и разрешён к показу, специализация совпала, грейд входит в запрошенный.

Полоски на карточке, шкала 0–100:

| Полоска | Откуда число |
| --- | --- |
| Результат теста | Балл запечатанного теста |
| Совпадение стека | Доля обязательных навыков вакансии, которые кандидат отметил. Если навыки не заданы — 100 |
| Достижения ФСП | 0, если истории нет. Иначе формула ниже |
| Соответствие потребности | Итоговый рейтинг. По нему сортируется список |

Достижения ФСП. Лучший результат: участие без места — 30, топ-10% — 60, 3 место — 75, 2 место — 85, 1 место — 100. Множитель уровня: вузовское 0,4, региональное 0,7, национальное 1,0, международное 1,2. Итог обрезается на 100. Второй результат добавляет 15% своей величины.

```text
сила = 0,70 × тест + 0,30 × ФСП
соответствие = (0,50 × сила / 100 + 0,35 × стек + 0,15 × вилка) × свежесть
```

`стек` и `вилка` здесь — доли от 0 до 1. Если у вакансии включено «сначала участники ФСП», сила считается как `0,55 × тест + 0,45 × ФСП` (поле API `prefer_fsp`, в форме создания выключено). Вилка — доля ожиданий кандидата, которая пересекается с вилкой вакансии. Ожидания не указаны — множитель 1. Вилки не пересекаются — 0. Свежесть: 1,00, если тесту меньше 90 дней, иначе 0,85.

Отметки «почему в топе» ставятся отдельно от процента: категория, стек, тест, ФСП, условия. Фильтр достижений ФСП формулу не меняет.

## Валидация подбора

Золотые метки лежат в сиде и не вычисляются формулой. Precision@5 — доля полностью релевантных (метка 2) в топе. 11 октября 2026, `GET /api/v1/admin/validation/summary`:

| Потребность | Precision@5 | Нерелевантные |
| --- | ---: | ---: |
| Middle Backend на Go | 1,000 | 0 |
| Middle Frontend, React | 0,750 | 0 |
| Middle QA | 0,667 | 0 |
| Senior Backend на Go | 0,333 | 0 |
| Среднее | 0,688 | 0 |

Порог спецификации — среднее не ниже 0,60 и доля чужих категорий в топе не выше 0,10. Оба выполнены. У Senior топ короткий: один релевантный и двое с неполным стеком, чужих категорий нет.

Стабильность повторных форм, разрыв сильного и слабого кандидата, экспертная разметка протоколов и пилот на пяти знакомых в этой сдаче не проводились. Числа по ним не заполнялись.

## Тест

Форма одна и та же по сложности, состав разный. 42 вопроса своего грейда, 12 нижнего, 6 верхнего. Около четверти — множественный выбор. Три практические задачи: разминка, целевая, выше грейда. У каждой 5 открытых тестов и 15 скрытых.

```text
балл = 100 × (0,5 × доля верной теории + 0,5 × доля верной практики)
```

Провал не понижает грейд. Смена запечатанного грейда — соседний уровень и не раньше чем через 90 дней после прохождения. Учебные `@example.com` после провала первого теста могут сдавать сразу. Обычный пользователь ждёт 7 дней.

Живой банк есть у Backend, Frontend и QA. Карта навыков и вопросы лежат в `data/` и открываются на `/skills`.
